## 2 · GitHub-Flow

  

### 9. Bringe die Schritte in die richtige Reihenfolge



`Commit · Issue · Pull Request · Branch`

  

**Meine Antwort:** Issue --> Branch --> Commit --> Pull Request

  

### 10. Was ist ein Issue?

  

**Meine Antwort:** Informationen zum Problem im Projekt

  

### 11. Was ist ein Branch?

  

**Meine Antwort:** Ein zusätzlicher Zweig, der den ursprünglichen Code nicht beeinflusst.

  

### 12. Warum arbeitet man für eine Änderung häufig auf einem eigenen Branch?

  

**Meine Antwort:** Um den main-Branch nicht zu berühren

  

### 13. Was ist ein Commit?

  

**Meine Antwort:** Änderungen speichern

  

### 14. Wozu dient eine Commit-Nachricht?

  

**Meine Antwort:** Beschreibung der Änderungen in Commit

  

### 15. Was ist ein Pull Request?

  

**Meine Antwort:** Antrag auf Hinzufügung von Änderungen zu main

  

### 16. Was bedeutet Review?

  

**Meine Antwort:** Den Code vor dem Hinzufügen zu main prüfen

  

### 17. Was bedeutet Merge?

  

**Meine Antwort:** Merge = Code zusammenführen

  

### 18. Wann sollte ein Pull Request gemergt werden?

  

**Meine Antwort:** Nach dem Review

## 3 · Wichtige Git-Begriffe und Befehle

  

### 19. Was bedeutet Push?

  

**Meine Antwort:** überträgt Commits an GitHub

  

### 20. Was bedeutet Pull?

  

**Meine Antwort:** Lädt neue Änderungen von GitHub

  

### 21. Was ist der Unterschied zwischen Commit und Push?

  

**Meine Antwort:** Commit speichert Änderungen in Git. Push sendet Commits an GitHub.

  

### 22. Was ist der Unterschied zwischen Pull und Pull Request?

  

**Meine Antwort:** Pull ruft Änderungen von GitHub ab. PR eordert an, Änderungen in einen anderen Branch zusammenzuführen.

  

### 23. Was bedeutet Clone?

  

**Meine Antwort:** Erstellt eine lokale Kopie des Repositorys

  

### 24. Was macht `git status`?

  

**Meine Antwort:** Zeigt den Dateistatus an

  

### 25. Was macht `git add`?

  

**Meine Antwort:** Fügt Änderungen am Staging-Area hinzu

  

### 26. Was ist die Staging Area?

  

**Meine Antwort:** Hier wählen Sie die Änderungen aus, die in den nächsten Commit übernommen werden sollen

  

### 27. Was macht `git log`?

  

**Meine Antwort:** Zeigt den Commit-Verlauf an

  

### 28. Was bedeutet Branch wechseln?

  

**Meine Antwort:** Springe von einem Branch zum anderen

  

### 29. Speichert `git add` bereits eine neue Version?

  

**Meine Antwort:** Nein

  

### 30. Speichert `git push` deine noch nicht committeten Dateiänderungen?

  

**Meine Antwort:** Nein
